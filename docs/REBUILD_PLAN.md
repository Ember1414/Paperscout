## 0. 如何使用本文件

### 0.1 给执行 agent

1. 开工前完整读一遍本文件 + `docs/ACCEPTANCE.md`。**不允许跳读第 1 章（约束）与第 10 章（验收）**。
2. 严格按第 9 章的任务包顺序施工：`M0 → M1 → … → M8`（9 个里程碑 / 86 个任务包）。同一里程碑内可并行，跨里程碑必须串行。
3. 每个任务完成后必须产出**验收证据**（见 8.2），证据缺失视为未完成。
4. 任何与本文冲突的"更优方案"，先写进 `docs/DECISIONS.md` 提案，等 owner 在验收时裁决；**不得先做后报**。
5. 禁止事项（硬性）见 1.4 与 1.5。触碰即回滚。

### 0.2 给验收者（owner）

1. 只按 `docs/ACCEPTANCE.md` 勾选，不需要读代码。
2. 每个里程碑验收一次，**不通过则不得进入下一里程碑**（避免缺陷堆积到最后一刻无法定位）。
3. 验收只信"可复现的证据"，不信口头描述。任一验收项无法当场复现即判不通过。
4. 验收时优先做**交互级操作**（点击、悬停、键盘、刷新、后退、断网），不要只看截图是否好看。历史经验：视觉正常但交互坏掉是本项目最常见的回归形态。

## 1. 约束与不变量（不可协商）

### 1.1 保持不变（硬约束）

| 编号 | 约束 | 判定方式 |
|------|------|----------|
| C-01 | 部署形态仍为 **Cloudflare Pages + Pages Functions**，静态产物目录仍为 `public/` | `wrangler.jsonc` 中 `pages_build_output_dir === "public"`；`npx wrangler pages deploy` 可直接发布 |
| C-02 | 绑定仍为 **KV（CACHE）+ D1（DB）+ Workers AI（AI）** 三类，可新增同类免费资源，不得新增付费资源 | `wrangler.jsonc` 审查 |
| C-03 | 保留 `warmer/` Cron Worker 角色（可重写实现，但保留定时预热能力） | 存在 `scheduled` 导出且被 `wrangler` 配置 |
| C-04 | 无构建步骤：`public/` 内的文件即线上文件，浏览器直接执行 | `npm run dev` 后 `public/` 无 `dist`/`build` 中间层 |
| C-05 | 域名与 API 前缀不变：`https://paperscout.pages.dev`，API 在 `/api/*` | 线上冒烟 |
| C-06 | 站点对访问者**完全免费**：无登录、无付费墙、无广告、无试用限制 | 全站扫描无 paywall/订阅/登录门 |

### 1.2 免费额度预算（设计前提）

> 以下为 Cloudflare 免费套餐的量级。**M0 第一天必须到官方文档核对当日数值并写入 `docs/BUDGET.md`**；若实际额度低于本表 50%，需回到本文件调整功能优先级。

| 资源 | 免费额度（量级） | 本项目的用法 | 预算上限（设计目标） |
|------|------------------|--------------|----------------------|
| Pages 构建 | 500 次/月 | 本项目不走构建，直接上传 | 0 |
| Functions 请求 | 100,000 次/天 | 全部 API | ≤ 20,000/天 |
| KV 读 | 100,000 次/天 | L2 缓存读取 | ≤ 10,000/天 |
| **KV 写** | **1,000 次/天** | **最稀缺资源** | ≤ 300/天 |
| D1 行读 | 5,000,000 行/天 | 统计、配额、笔记 | ≤ 300,000/天 |
| D1 行写 | 100,000 行/天 | 统计、配额、笔记 | ≤ 5,000/天 |
| Workers AI | 10,000 Neurons/天 | 摘要/翻译/问答 | ≤ 6,000/天（留 40% 余量） |
| Analytics Engine | 100,000 数据点/天（写入） | 检索日志、源健康 | ≤ 20,000/天 |

**由此推导出的三条铁律**（违反即架构错误）：

1. **KV 只读不写（热路径）**。任何"每个请求都写 KV"的实现一律禁止，包括熔断计数、热词累加、健康状态。
2. **响应缓存放 L1 = Cache API（`caches.default`，无写配额）**，KV 仅作为 Warmer 预热的 L2 热点层。
3. **一切 AI 调用必须先查缓存、再查配额、最后才调用模型**，且必须可降级为非 AI 结果。

### 1.3 边界与替代实现（"不做什么"必须给出"改做什么"）

> 原则：**功能要全，但不靠违规/付费/不确定的手段实现**。每条"不做"后面必须跟一个能在免费额度内落地的替代方案；没有替代方案的，才真正排除。

| 编号 | 不做的形态 | 替代实现（必须做） | 原因 |
|------|-----------|-------------------|------|
| N-01 | 账号密码 / 邮箱验证 / OAuth 登录 | **本地多工作区**（可建多个库）+ **可选端到端加密云备份**（浏览器生成密钥，D1 只存密文 blob，1 行/次） | 无邮件服务；加密备份既满足"换设备"又不牺牲隐私 |
| N-02 | 知网/万方/维普全文抓取 | 开放元数据四通道（OpenAlex zh / Crossref CJK / DOAJ / ChinaXiv）+ 覆盖范围明示 + "去知网检索"外链提示 | 违反 ToS，法律风险 |
| N-03 | 百度学术 HTML 爬虫 | 同上四通道；把"中文召回"做成可解释的**覆盖率提示**而非假装完整 | 反爬不稳定、违反 ToS、无法在免费额度下维护 |
| N-04 | PDF 全文托管/镜像/下载代理 | **Unpaywall/OpenAlex OA 位置探测**（合法免费）→ 只给正版直链；无 OA 时给"机构访问/作者主页/预印本"三路建议 | 版权风险 |
| N-05 | 全库向量索引（Vectorize 大规模索引） | **池内语义重排**：仅对本次结果池 Top 50 做 embedding 重排（每次 ≤ 1 次 batch 调用，配额内），失败自动回退 BM25 | 免费额度与语料规模不匹配 |
| N-06 | 需机构资质的源（IEEE/Scopus/Springer/BASE） | 提供**可选源插槽**（`config.sources.optional`）+ `/settings` 中填 key 的入口（key 仅存本地，经请求头透传，不落库）；owner 申请到即插即用 | 默认必须零 key 可用 |
| N-07 | 社交（关注他人/评论/点赞） | **只读分享链接**（结果集/证据表快照，短链存 D1 单行）+ 分享者可附一句说明 | 与定位无关，但协作需求真实存在 |
| N-08 | 自建后端/其他云/容器 | Cloudflare Pages + Functions 内实现一切（含定时、队列式预热、SSE） | 违反 C-01 |
| N-09 | 付费 LLM API | Workers AI（免费额度）+ 严格配额 + 缓存 + 降级；模型可路由到更省 neuron 的小模型 | 违反 C-06 |
| N-10 | 第三方图表/图谱 CDN 库 | 自绘 canvas/SVG（折线、柱状、散点、网络图、时间轴、热力日历） | 隐私 + 体积 + 可用性 |
| N-11 | 全文语义搜索（对 PDF 正文建索引） | 只对**标题+摘要+关键词**做检索与重排；正文交给原文阅读器 | 无全文存储权与算力 |
| N-12 | 邮件/WebPush 通知 | **站内通知中心**（Cron 每日写入 D1 的新论文快照 + 首页角标 + `/notifications` 页），用户主动查看 | 无邮件服务；WebPush 需要额外密钥与 VAPID 维护 |

### 1.4 技术决策基线（已定，agent 不得自行更改）

| 编号 | 决策 | 理由 | 若被推翻的代价 |
|------|------|------|----------------|
| D-01 | 前端保持**零构建原生 ES Modules**（无 npm runtime 依赖） | 满足 C-04；部署链路最短；避免构建产物与 `public/` 不一致 | 需改部署流程，违反 C-01 |
| D-02 | 前端不引入框架，采用"模板函数 + 局部重渲染"的组件约定（见 7.2） | 同上；本项目交互复杂度可控（约 20 个视图） | — |
| D-03 | **移除百度学术爬虫源**，中文覆盖改为四通道（OpenAlex zh / Crossref CJK / DOAJ / ChinaXiv）并在 UI 标注覆盖范围 | 合规 + 稳定 + 可维护；爬虫是最大不确定性来源 | 中文独家文献召回下降；需 owner 在 M1 验收时确认 |
| D-04 | 数据源**分四档、共 19 个**（核心 6 / 学科 6 / 开放 4 / 可选插槽 3），单次检索实际调用 **上限 9 个**；新增源必须先通过冒烟探测（见附录 A） | 既要"全面"，也要控制噪声与上游压力；档次化让覆盖面与质量同时最大化 | 若全部默认开启：噪声与限流激增 |
| D-05 | 无账号。身份 = 本地 `client_id`；用户数据存 IndexedDB；可选**端到端加密云备份**（D1 存密文） | 免费 + 隐私（服务器看不到明文） | 不做加密备份则跨设备需手导 |
| D-06 | 排序 = **本地重排**（BM25 + 质量先验），不依赖上游排序 | 跨源不可比；本地重排可解释、可测试 | — |
| D-07 | 分页 = **结果池游标**（一次召回 200 条池化，页从池中切片） | 修复 v2 跨源分页错位（见 A-02） | 深翻页需追加召回 |
| D-08 | AI 采用"检索 → 证据筛选 → 生成 → 引用校验"四段式，**引用不可校验即降级为拒答** | 零幻觉是产品底线 | — |
| D-09 | **功能完整性优先于工期**：P0 功能表（2.5）未全绿不得发布 1.0 | 用户要求"功能全面"，砍功能必须走 owner 裁决 | 工期延长（见第 9 章，46 个工作日） |
| D-10 | 检索结果**永远先给"纯检索可用"**，AI/语义重排都是增强层，任何一层挂掉不影响出结果 | 可用性 > 智能感 | — |
| D-11 | 所有"新增数据"（笔记/标签/工作区/分享）**默认只存本地**，只有用户显式开启才上云（且加密） | 隐私默认最强 | 跨设备体验稍弱 |
| D-12 | 一切"分析类"数字（趋势、被引增速、主题热度）必须标注**计算口径与数据时间**，无数据时显示"—"而非 0 | 学术场景下"假数字"比没数字更糟 | — |

### 1.5 硬性禁令（工程红线）

1. 禁止 `catch {}` 静默吞掉上游/解析错误而不记录：每个 catch 必须 `log` 或返回带 `code` 的错误对象。
2. 禁止把上游原始错误文本直接回显给用户（v2 的 `'服务器内部错误：' + detail` 属反例）。
3. 禁止在客户端 `innerHTML` 拼接未转义的上游文本；统一走 `html` 模板函数的自动转义。
4. 禁止新增任何 `dependencies`（runtime 依赖）。`devDependencies` 允许，但仅限类型/测试工具。
5. 禁止修改 `wrangler.jsonc` 中已有的 `binding` 名称（`CACHE`/`DB`/`AI`），只允许新增。
6. 禁止删除或重命名 `/api/search`、`/api/sources`、`/api/trending`、`/api/health`（对外契约向后兼容，新增能力走新端点或新参数）。
7. 禁止在代码里写死 `paperscout.pages.dev`（Warmer 除外，改为读环境变量 `TARGET_ORIGIN`）。
8. 禁止提交 `.wrangler/`、`node_modules/`、任何含密钥的文件。

## 2. 产品定位

### 2.1 一句话

**PaperScout 是一个"证据可溯源"的学术研究工作台：帮研究者在 60 秒内从"一个模糊问题"走到"一份可引用的文献清单"。**

不做的自我定位：不是搜索引擎的皮肤，不是 AI 摘要器，不是文献管理器。

### 2.2 目标用户与场景

| 用户 | 场景 | 现在的痛点 | v3 必须给出的答案 |
|------|------|-----------|-------------------|
| 研究生（开题） | "这个方向有哪些必须读的论文？" | 挨个库搜、结果重复、不知道从哪篇读起 | 一次检索 → 按影响力/时效分层 → 一键生成"入门阅读路径"（5 篇必读 + 5 篇前沿） |
| 博士生/青椒（写综述） | "我需要一个可追溯的证据表" | 手工整理 Excel，引用格式反复改 | 勾选 → 证据表（年份/方法/数据/结论/局限）→ 导出 CSL-JSON/Markdown |
| 工程师（技术选型） | "这个方法在工业界有没有验证？" | 中文资料噪声大、预印本与期刊混在一起 | 文献类型/ venue 类型/ 是否同行评审 三维筛选 + 中国作者/机构过滤 |
| 跨语种研究者 | "中文成果和国际成果要一起看" | 两个库分别搜，无法对齐 | 中英双语摘要 + 同一论文的多源元数据融合 + 中文覆盖范围明示 |

### 2.3 与同类产品的差异（必须体现在 UI 上，而不只是文案）

| 能力 | Google Scholar | Connected Papers | Elicit | 知网 | **PaperScout v3** |
|------|----------------|------------------|--------|------|-------------------|
| 多源聚合去重 | 部分 | 否 | 部分 | 单一库 | **是，且展示"来源证据"** |
| 排序可解释 | 否 | 否 | 部分 | 否 | **是，每条结果给出排序理由** |
| 中文 + 英文同屏 | 部分 | 否 | 否 | 仅中文 | **是，含覆盖范围声明** |
| 元数据置信度 | 否 | 否 | 否 | 否 | **是（A/B/C 三级，来自源数决定）** |
| 零幻觉 AI | — | — | 弱 | 否 | **强：引用逐条校验，不可校验即拒答** |
| 免费且无登录 | 是 | 限次 | 否 | 否 | **是** |
| 证据表/综述骨架导出 | 否 | 否 | 是（付费） | 部分 | **是** |
| 数据留在本地 | 否 | 否 | 否 | 否 | **是（文库存 IndexedDB）** |
| 引文网络 + 引用上下文 | 否 | 有（仅图） | 否 | 否 | **有（图 + 在哪句话被引）** |
| 作者/机构/期刊画像 | 部分 | 否 | 否 | 否 | **有（h-index、时间线、接收主题）** |
| 订阅与增量提醒 | 有（邮件） | 否 | 否 | 有（邮件） | **有（站内通知中心，无需邮箱）** |

### 2.4 指标（护栏指标优先于增长指标）

本产品无商业化目标，指标用于判断"是否真的更好用"，而不是增长。

| 类型 | 指标 | 目标 |
|------|------|------|
| 北极星 | **有效检索率** = 一次检索后 60 秒内发生"打开原文/收藏/加入证据表"的会话占比 | ≥ 35% |
| 质量 | 首屏结果人工相关性（金标准集 Top-10 命中率） | ≥ 70% |
| 质量 | 重复记录率（同一论文出现两次） | ≤ 1% |
| 质量 | AI 回答引用可校验率 | 100%（不可校验必须降级） |
| 性能 | 热查询 P95 端到端 | ≤ 1.2s |
| 性能 | 冷查询 P95 端到端 | ≤ 6.5s |
| 性能 | LCP（4G 模拟） | ≤ 2.5s |
| 成本 | 日 KV 写次数 | ≤ 300 |
| 稳定 | 检索接口 5xx 率 | ≤ 0.5% |
| 稳定 | 单源故障时检索可用率 | 100%（降级不失败） |

### 2.5 功能全景（Feature Map）

> **判定标准**：每个功能必须回答"谁在什么场景下会用它"。答不上来的一律不做（不是排后，是不做）。
> **优先级**：`P0` = 1.0 必须全绿（D-09）；`P1` = 1.0 尽量做，工期紧张可移入 1.1（不影响发布判定）；`P2` = 明确不做，只记录想法。
> **规模**：共 **109 项**功能点（P0 80 / P1 20 / P2 9），任务包见第 9 章。

#### A. 检索与查询（21）

| 功能 | 解决什么真实问题 | P | M |
|------|------------------|---|----|
| 多源并行聚合检索 | 一个个库搜太慢 | P0 | M1 |
| 智能去重合并（并查集 + DOI 优先） | 同一篇论文重复出现 5 次 | P0 | M1 |
| 结果池分页（无重复无漏） | 翻页出现重复/漏条 | P0 | M1 |
| 自然语言查询解析 | 不知道怎么拼检索式 | P0 | M1 |
| 高级检索构建器（字段 + AND/OR/NOT 分组） | 精确检索需要语法，记不住 | P0 | M2 |
| 检索式 DSL（`author:` `year:` `venue:` `type:` `doi:` `-排除` `"短语"`） | 一次表达复杂需求 | P0 | M1 |
| DOI / 标题直达 | 拿到 DOI 只想看这篇 | P0 | M1 |
| 字段筛选（年份/类型/语言/学科/来源/OA/顶刊会议） | 结果太杂 | P0 | M2 |
| 二次检索（在当前结果内再搜） | 1000 条里找子方向 | P0 | M2 |
| 排序（智能/相关/最新/被引/OA 优先） | 不同任务要不同顺序 | P0 | M1 |
| 排序可解释（理由 chip） | 不知道为什么排第一 | P0 | M1 |
| 查询建议（拼写纠正 + 相关术语 + 同义扩展） | 关键词选得不对，召回差 | P0 | M2 |
| 中英关键词互译扩展 | 中文搜不到英文成果，反之亦然 | P0 | M2 |

### 4.2 URL 状态契约（可分享性）

所有可交互状态必须落在 URL 上，刷新/后退/分享必须完全还原。

```
/search
  q          string   必填，支持 DSL（见附录 B）
  src        csv      arxiv,openalex,crossref,s2,pubmed,dblp,doaj,europepmc,zenodo（缺省 core 集）
  from,to    int      年份
  type       enum     all|journal|conference|preprint
  lang       enum     all|zh|en
  field      csv      cs|physics|math|bio|med|econ
  sort       enum     smart|relevance|newest|cited
  page       int      1..N（默认 1）
  limit      int      20|50（默认 20）
  view       enum     list|compact|table（默认 list）
  sel        string   当前打开的详情（work id），用于抽屉深链
```

规则：
- 默认值不进 URL（`sort=smart`、`lang=all` 等省略），保证链接短。
- 任何筛选变更 → `history.pushState`；翻页 → `pushState`；抽屉开合 → `replaceState`（避免污染后退栈）。
- 进入 `/search` 时若 URL 无 `q`，重定向到 `/`。

## 5. 核心能力设计

### 5.1 检索：查询理解与召回编排

#### 5.1.1 查询解析（`lib/query/parse.ts`）

输入：原始字符串 + URL 参数。输出：`ParsedQuery`。

```ts
interface ParsedQuery {
  raw: string;
  terms: string[];            // 归一化检索词（去停用词、大小写折叠、CJK 分词）
  phrases: string[];          // 引号短语
  excluded: string[];         // -term
  fieldTags: { key: string; value: string }[]; // author: / venue: / year: / doi: / type:
  intent: 'topic' | 'author' | 'doi' | 'title' | 'question';
  lang: 'zh' | 'en' | 'mixed' | 'unknown';
}
```

规则：
- `10.xxxx/...` 形态 → `intent = 'doi'`，走 DOI 直查（OpenAlex/Crossref），跳过 fan-out。
- 引号内 → `phrases`，优先给支持精确短语的源（Crossref `query.bibliographic`、S2）。
- `author:xxx`、`year:2020-2024`、`venue:NeurIPS`、`type:preprint` 为显式字段过滤。
- 含 `?`/`如何`/`为什么` 且长度 > 12 → `intent = 'question'`，UI 提示"要不要直接问 AI（带证据）"。
- 中文分词：**不引入词典**。策略：CJK 串按 2-gram 切分用于 BM25（`大语言模型` → `大语/语言/言模/模型`），同时保留整串用于精确短语加权。理由：零依赖、对中文召回足够（附录 B 有示例）。
- 停用词表内置中英双语（约 120 词），可通过 `lib/query/stopwords.ts` 维护。

#### 5.1.2 召回编排（`lib/search/orchestrator.ts`）

```
             ┌──────────── 5.1.1 解析 ────────────┐
             ↓                                     │
    DOI? ──是──→ 直查（OpenAlex→Crossref 兜底）     │
             │否                                    │
             ↓                                     │
  源选择（能力矩阵 + 查询语言 + 用户勾选）            │
             ↓                                     │
  ┌── 并发 fan-out（最大 6 并发）──────────────┐     │
  │  每源预算：AbortController 4.5s 软超时      │     │
  │  全局预算：6.5s 硬截止（剩余结果照常返回）   │     │
  └───────────────────────────────────────────┘     │
             ↓                                     │
   归一化 → 融合去重（5.2） → 本地重排（5.3）         │
             ↓                                     │
   结果池（200 条）写入 L1 Cache API（TTL 10min）────┘
             ↓
   分页切片（5.4）→ 响应
```

关键数值（可调，但必须在 `lib/config.ts` 中集中定义）：

| 参数 | 值 | 说明 |
|------|-----|------|
| `PER_SOURCE_TIMEOUT_MS` | 4500 | 单源软超时 |
| `TOTAL_BUDGET_MS` | 6500 | 整体硬截止，超时源标记 `timeout` 并返回已得结果 |
| `MAX_CONCURRENCY` | 6 | 避免 Workers 子请求数与上游限流叠加 |
| `POOL_TARGET` | 200 | 结果池目标条数（去重后） |
| `PER_SOURCE_LIMIT` | 50 | 单源单次召回上限 |
| `CACHE_TTL_S` | 600 | 结果池 TTL |
| `RETRY` | 1 次（仅 429/5xx，退避 400ms + 抖动） | 降低重试放大；v2 的 4 次重试是 429 的放大器 |

**源能力矩阵**（决定"哪些源参与本次召回"，避免无效调用）：

| 源 | 支持年份过滤 | 支持类型过滤 | 支持作者 | 返回摘要 | 返回引文数 | 返回 PDF | 中文覆盖 | 默认 |
|----|------|------|------|------|------|------|------|------|
| OpenAlex | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 强 | ✅ 核心 |
| Crossref | ✅ | ✅ | ✅（query.author） | 部分 | ✅ | 少 | 中 | ✅ 核心 |
| arXiv | ✅（日期） | 仅预印本 | ✅ | ✅ | ❌ | ✅ | 无 | ✅ 核心 |
| Semantic Scholar | ✅ | 部分 | ✅ | ✅ | ✅ | ✅ | 弱 | ✅ 核心 |
| PubMed | ✅ | 仅期刊 | ✅ | ✅ | ❌ | 部分 | 无 | ✅ 核心 |
| DBLP | ❌（客户端过滤） | 会议为主 | ✅ | ❌ | ❌ | ❌ | 无 | ✅ 核心 |
| DOAJ | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ | 中 | ○ 扩展 |
| Europe PMC | ✅ | ✅ | ✅ | ✅ | ✅ | 部分 | 无 | ○ 扩展 |
| Zenodo | ✅ | 否 | 部分 | 部分 | ❌ | ✅ | 弱 | ○ 扩展 |

上表为核心 9 源；其余 10 个（HAL / SciELO / J-STAGE / bioRxiv / DataCite / ChinaXiv / IEEE / Springer / Scopus 等）的能力字段在其 `registry.ts` 声明中定义，并遵循附录 A 的冒烟探测与 9 源上限。

规则：查询命中 `intent=doi` 时只走 OpenAlex + Crossref；`lang=zh` 时必带 OpenAlex（`language:zh`）与 Crossref（CJK 过滤）；`type=preprint` 时移除 PubMed/DOAJ。

#### 5.1.3 上游调用规范

- 统一 `fetchUpstream(url, { timeoutMs, retry, source })`：返回 `{ ok, status, data, elapsedMs, error? }`，**永不抛异常给编排层**。
- 必须设置 `User-Agent: PaperScout/3.0 (+https://paperscout.pages.dev; mailto:<真实邮箱>)`。
- OpenAlex 必须带 `mailto`（写入 `lib/config.ts` 的 `CONTACT_EMAIL`，M0 时由 owner 提供真实邮箱，缺省用 `admin@paperscout.pages.dev`）。
- 禁止在请求路径里做 HTML 解析（爬虫只允许在 Warmer 的定时任务中做，且只针对 arXiv Atom API，不做 HTML）。

### 5.2 记录融合（Entity Resolution）

目标：同一篇论文在 6 个源里出现 6 次，最终只出现 1 次，且**保留全部来源证据**。

#### 5.2.1 统一实体

```ts
interface Work {
  id: string;                 // 稳定主键：doi 归一 > 标题指纹 hash
  title: string;              // 最长且非截断者
  authors: { name: string; sourceRank: number }[];
  year?: number;
  venue?: string;
  venueType: 'journal'|'conference'|'preprint'|'repository'|'unknown';
  abstract?: string;          // 最长非空
  doi?: string;               // 归一化小写
  url: string;                // 优先级：doi.org > 出版社 landing > 源 url
  pdfUrl?: string;
  citations?: number;         // 见 5.2.4 口径统一
  citationsBySource: Record<string, number>;
  type: 'journal'|'conference'|'preprint'|'other';
  openAccess: boolean;
  lang: 'zh'|'en'|'other';
  sources: Provenance[];      // 每个源一条，不合并、不覆盖
  confidence: 'A'|'B'|'C';    // 元数据置信度
  score?: { total: number; parts: Record<string, number> }; // 5.3
}

interface Provenance {
  source: SourceId;
  sourceName: string;
  fetchedAt: number;
  raw: { url?: string; doi?: string; citations?: number; type?: string };
}
```

#### 5.2.2 归一化规则（`lib/fusion/normalize.ts`，纯函数，必须单测）

| 字段 | 规则 |
|------|------|
| DOI | 去 `https://doi.org/`、`doi:` 前缀；转小写；去尾部 `.,;` 与空白；`10.` 前缀校验，非法则丢弃 |
| 标题 | Unicode NFKC → 去 HTML 实体 → 去所有标点/空白 → 小写；同时生成"去副标题"版本（按 `:`/`：`/`—` 首次出现切分） |
| 作者 | 去 `*`/`†` 等标记；`Last, First` → `First Last`；NFC；小写用于比对 |
| 年份 | 取 4 位数字，范围 1800..当前年+1；越界丢弃 |
| Venue | 去首尾空白、去 "Proceedings of the" 前缀、小写用于比对（展示保留原样） |
| 摘要 | 去 JATS 标签（Crossref 常见）、去多余空白；保留最长版本（≤ 3000 字） |

#### 5.2.3 合并算法（顺序合并 + 并查集）

```
1. 全部记录按"证据强度"排序：有 DOI > 有年份+作者 > 仅有标题
2. 对每条记录计算候选 key：
   k1 = doi:<normalized doi>
   k2 = title:<title fingerprint>
   k3 = title-sub:<去副标题指纹>|<year>|<firstAuthorSurname>
3. 并查集合并：
   - k1 命中即合并（最高优先，冲突时 DOI 胜）
   - k2 命中且年份差 ≤ 1 → 合并
   - k2 命中但年份差 > 1 → 不合并（可能是同名不同文），除非 k3 也命中
   - k3 命中且标题相似度 ≥ 0.92（Dice 系数，2-gram）→ 合并
4. 合并后字段择优（见 5.2.4），provenance 全量保留
```

**禁止**：链式单 Map 合并（v2 的 `byKey` 单键 Map 会让 A≈B、B≈C 但 A≠C 的记录错误串联）。并查集 + 传递闭包后，需再跑一次"簇内一致性校验"：若簇内出现两个不同 DOI，则拆分为独立簇（DOI 是最强证据）。

#### 5.2.4 字段择优与口径统一

| 字段 | 择优规则 |
|------|----------|
| title | 长度最长且不以 `…` 结尾者；同长度取非全大写 |
| abstract | 最长者；若含 `<jats:` 则先清洗 |
| year | 多源一致则取一致值；不一致取"正式出版源"（Crossref > OpenAlex > 其他）；仅预印本时取最早 |
| venue | 优先非空且不含 "bioRxiv"/"arXiv" 的正式 venue；同优先级取最长 |
| citations | **不做 max**。取"口径最新且覆盖最全"的单一源：优先 OpenAlex（`cited_by_count`），无则 S2，无则 Crossref；同时在 `citationsBySource` 保留各源数值，UI 悬浮显示"OpenAlex 1,203 / Crossref 980" |
| url | `https://doi.org/<doi>` > 出版社 landing > 源 URL（去 tracking 参数） |
| pdfUrl | 优先 OA 直链（`best_oa_location.pdf_url`）> 其他；必须是 https 且非登录墙域名黑名单 |
| type | journal > conference > preprint 的"最强主张"；仅当所有源都是 preprint 才判 preprint |
| openAccess | 任一源 `is_oa === true` 即 true（OA 是"存在性"事实） |

#### 5.2.5 置信度分级（UI 必须展示）

| 级别 | 条件 | 展示 |
|------|------|------|
| A | DOI + ≥ 2 个源 + 有年份与 venue | 绿色"元数据可信" |
| B | DOI 单源，或 无 DOI 但 ≥ 2 源字段一致 | 灰色"单源校验" |
| C | 仅 1 源且无 DOI | 黄色"待核实" |

#### 5.2.6 验收指标

- 金标准集（附录 F）中每条的重复率 ≤ 1%。
- 人工抽检 30 条合并结果：错误合并（不同论文被合并）≤ 1 条。

### 5.3 排序（可解释）

#### 5.3.1 打分公式

```
total = 1.00 * relevance
      + 0.55 * quality
      + 0.20 * recency
      + 0.10 * availability
      + 0.05 * agreement
```

| 分项 | 计算 | 说明 |
|------|------|------|
| `relevance` | BM25（k1=1.2, b=0.75）× 字段权重（title×2.2, abstract×1.0, venue×0.3）+ 短语命中 +1.5 + 标题完全匹配 → 置顶（+5） | 语料 = 本次结果池（200 条），IDF 在池内计算 |
| `quality` | `log10(citations+1)/3` 截断到 [0,1]；venue 白名单（Nature/Science/Cell/ICML/NeurIPS/ACL/CVPR…）额外 +0.15 | 无引文数按 0 处理（不惩罚新论文过多） |
| `recency` | 指数衰减：`exp(-age/6)`，age 单位年；预印本 age 用提交年 | 6 年半衰 |
| `availability` | OA +0.5，有 PDF +0.5（0..1） | 让"能立刻读"的排前 |
| `agreement` | `min(sources.length, 3)/3` | 多源一致 ≈ 更可信 |

- 用户切换 `sort=cited|newest` 时**只按该键排序**（不做加权），保证"所见即所得"。
- `sort=relevance` 时只用 `relevance`。
- 排序必须在**融合后**进行（v2 已如此，保留）。

#### 5.3.2 解释生成（`lib/search/explain.ts`）

为每条结果生成 1–3 个理由 chip，按贡献度取前三，文案预置：

| 触发条件 | chip 文案 |
|----------|-----------|
| relevance > 0.8 且标题含全部词 | `标题完全匹配` |
| citations ≥ 100 | `高被引 1.2k` |
| citations 在池内 Top 10% | `本主题高影响` |
| age ≤ 1 | `近 12 个月` |
| openAccess && pdfUrl | `可下载 PDF` |
| sources.length ≥ 3 | `3 源一致收录` |
| venue 在白名单 | `顶会/顶刊` |
| type === 'preprint' && age ≤ 1 | `最新预印本` |

**要求**：chip 必须由 `score.parts` 真实推导，禁止写死或随机；单测需断言"每个 chip 的触发条件与分值一致"。

### 5.4 分页（结果池模型）

问题：v2 每页独立 fan-out，去重后页码无意义（A-02）。

方案：

1. 首次检索（page=1）召回 `POOL_TARGET=200` 条，融合排序后存入 L1 缓存，key = `pool:<queryHash>`（**不含 page/limit**）。
2. `page=N` 从池中切片 `[(N-1)*limit, N*limit)`。
3. 当 `N*limit > pool.length` 且池未耗尽（`exhausted=false`）→ 触发"追加召回"（各源 offset+50，最多 3 轮），合并进池后再切片。
4. 池耗尽后返回 `hasMore=false`，前端显示"已到末尾（共 N 条）"。
5. 响应必须带：`poolSize`、`hasMore`、`exhausted`、`partial`（是否有源超时）。

**约束**：`page` 上限 10（v2 是 20，但池模型下 > 10 页价值低）；超出返回 400 并提示"请缩小筛选范围"。

### 5.5 论文详情页

数据来源：`/api/work?id=`（新端点）。

- 若 `id` 为 DOI：OpenAlex 直查 → 失败 Crossref。
- 若 `id` 为标题指纹：先查池缓存，再 OpenAlex 标题搜索。
- 返回：完整 Work + `references`（最多 20）+ `citedBy`（最多 20，按被引排序）+ `similar`（5 条，OpenAlex `related_works`）。
- 所有外部字段必须标注来源与抓取时间（"被引数据：OpenAlex · 2026-10-24"）。
- 摘要在 300 字以上时默认折叠，展开不重新请求（一次返回全文）。
- 翻译**不自动触发**（省配额），用户点"译为中文"才请求 `/api/translate`。

### 5.6 作者页与主题追踪

**作者页** `/a/:id`：完整规格见 **5.12.1**。此处只记两条硬要求：
- 同名消歧必须先列候选让用户选，**禁止**自动取第一个（v2 的行为见 `services.ts:184`）。
- `/api/author` 必须一次返回身份卡 + Top10 + 时间线聚合数据，禁止前端串行 4 次往返。

**主题追踪** `/topics`（订阅列表）与 `/topics/:slug`（单主题详情）：
- 主题 = 保存的检索式（含筛选），或作者/期刊订阅。
- 展示：近 24 个月产出趋势（OpenAlex `group_by=publication_date`）、最新 20 条、Top venue、Top 作者。
- 增量：本地记录 `lastSeenAt` + 已见 id 集合（≤ 200），再次访问高亮"新增 N 篇"。
- 细节见 **5.13**；不做邮件/推送（N-12）。

### 5.7 文库与导出

- 存储：**IndexedDB 为主**（DB `paperscout`，stores：`works`/`collections`/`notes`/`searches`/`topics`/`settings`/`trash`）；D1 只存匿名统计、AI 配额、分享快照与**加密备份**，不存明文用户内容（隐私 + 写预算）。
- 收藏动作：0 网络请求，立即生效；云端同步仅在用户开启"加密备份"时发生（P1，见 5.16）。
- 标签/集合：多对多；支持批量打标。
- 笔记：Markdown 子集（粗体/列表/链接/公式用 KaTeX 风格 `$...$` 原样保存不强渲染）。
- 导出格式（全部纯前端生成，`Blob` 下载）：
  - BibTeX（`@article/@inproceedings/@misc` 按 type 选择，key = `姓+年+首词`，冲突加 `a/b`）
  - RIS（`TY` 按 type 映射）
  - CSL-JSON（供 Zotero/Word 插件）
  - CSV（标题/作者/年份/venue/DOI/被引/OA/URL/标签/笔记）
  - Markdown 证据表
- 导入：接受上述 JSON/CSV 回灌（幂等，按 `work.id` 去重）。

### 5.8 综述工作台（P0：证据表与骨架均属 1.0 范围）

四步向导（单页分步，状态存 URL + IndexedDB）：

1. **选文献**：从搜索结果/文库勾选（≤ 30 篇）。
2. **抽证据**：对每篇生成结构化条目（由 AI 完成，逐篇调用，可跳过；无 AI 时用规则抽取：年份/venue/被引/OA）。
3. **分组**：AI 给出 2–5 个主题簇（附簇名与成员），用户可拖动调整。
4. **产出**：
   - 证据表（可编辑表格，字段：文献 / 年份 / 方法 / 数据 / 主要结论 / 局限 / 我的备注）
   - 综述骨架 Markdown（背景 → 主题簇 → 分歧 → 空白 → 参考文献列表），**每句必须有 `[n]` 引用**
   - 导出的每个数字/结论必须可点击回原文（导出为 Markdown 时保留链接）

硬规则：AI 不得引入文献之外的事实；生成后用 5.9.3 的引用校验器验证，失败则该段标注 `⚠️ 待核实` 而不是删除。

### 5.9 AI 层（零幻觉是底线）

#### 5.9.1 能力与端点

| 端点 | 能力 | 模型 | 缓存 | 配额 |
|------|------|------|------|------|
| `POST /api/ai/summarize` | 一组文献的研究现状（300 字） | llama-3.3-70b-instruct-fp8-fast | 结果集 hash，24h | 全局 120/天，单 client 8/天 |
| `POST /api/ai/ask` | 带证据的回答（SSE 流式） | 同上 | 问题归一化 hash，24h | 全局 80/天，单 client 5/天 |
| `POST /api/ai/extract` | 单篇结构化抽取（贡献/方法/局限） | 同上 | work id + 摘要 hash，7d | 全局 150/天，单 client 20/天 |
| `GET /api/translate` | 摘要翻译（保留兼容） | m2m100 → LLM 兜底 | 文本 hash，24h | 全局 200/天 |

#### 5.9.2 Prompt 契约（必须写入 `lib/ai/prompts.ts`，单测断言包含关键约束句）

System（summarize / ask 共用骨架）：

```
你是学术文献分析助手。只能使用 <evidence> 中提供的内容作答。
规则：
1. 每个事实性论断后必须标注 [编号]，编号必须来自 <evidence>。
2. 不允许推断作者意图、不允许补充 evidence 之外的背景知识。
3. 若 evidence 不足以回答，只输出：INSUFFICIENT_EVIDENCE
4. 不确定时明确写"文献未说明"。
5. 输出简体中文，不使用感叹号，不堆形容词。
```

User 组装：`<question>` + `<evidence>[1] 标题\n摘要节选…</evidence>`；单条摘要截断 600 字，总预算 ≤ 6000 字。

#### 5.9.3 引用校验器（`lib/ai/verify.ts`，纯函数，必须单测）

```ts
function verifyCitations(answer: string, sources: SourceRef[]): {
  ok: boolean;
  invalidIds: number[];
  citedIds: number[];
  reason?: 'no_citation' | 'invalid_citation' | 'insufficient';
};
```

规则：
- 提取 `\[(\d+)\]`；若为空 → `no_citation` → 前端显示"AI 未给出可核实引用"，**不展示正文**。
- 任一编号 ∉ `[1..sources.length]` → `invalid_citation` → 剔除该句并标注，`ok=false`。
- 输出含 `INSUFFICIENT_EVIDENCE` → 展示"现有文献不足以回答"，并给出 3 条最相关文献。
- 单测覆盖：正常、越界、无引用、混合、连续编号 `[1][2]`、范围 `[1-3]`（视为 1,2,3）。

#### 5.9.4 配额与降级

```
请求 → 输入校验（长度/篇数）
     → 缓存命中？（KV 读，key 含 model+promptVersion）
     → 全局日配额（D1 表 ai_usage，按天聚合，1 次写/调用）
     → 单 client 日配额（D1，同上）
     → 调用 Workers AI（超时 20s，失败 1 次重试）
     → 引用校验 → 写缓存（L1 + KV，TTL 24h）
     → 返回（含 quota: { remaining, resetAt }）
```

超额响应：`429` + `{ code: 'AI_QUOTA_EXCEEDED', resetAt }`，前端文案"今日 AI 额度已用完（免费额度保护），明天 00:00 UTC 重置；文献检索不受影响"。

**禁止**：AI 失败时返回 500 给用户；必须降级为"仅证据列表"。

#### 5.9.5 流式

`/api/ai/ask` 支持 `Accept: text/event-stream`：`data: {"delta":"..."}` … `data: {"done":true,"citations":[...]}`。
前端用 `ReadableStream` 逐字渲染；不支持 SSE 时回退整段返回。

### 5.11 论文详情：引文、OA 探测与阅读体验

#### 5.11.1 正版全文探测（`services/availability.ts`）

优先级链（全部免费、无 key）：

```
1. OpenAlex best_oa_location.pdf_url（已在 Work 里）
2. Unpaywall: GET https://api.unpaywall.org/v2/{doi}?email=<CONTACT_EMAIL>
   → best_oa_location.url_for_pdf / oa_locations[]（版本：published/accepted/submitted）
3. Europe PMC（生医）：已含 PMCID 的直接给 PMC 全文链接
4. arXiv：DOI 反查 arXiv id（若标题命中 arXiv 池）
5. 兜底建议（不是链接）：机构图书馆 DOI 解析、作者主页 Google 搜索链接（标注"站外搜索"）
```

返回结构必须带 `kind`（publisher / repository / preprint / pmc）与 `version`（published / accepted / submitted），UI 用不同徽章，避免用户把预印本当正式版引用。

缓存：`avail:<doi>` KV 24h（仅首次写）。

#### 5.11.2 引文网络（`services/citations.ts` + `ui/chart.js` 的 net 模式）

- 数据：OpenAlex `referenced_works`（出边）+ `cited_by_api_url`（入边计数）+ S2 `references` / `citations`（含 `contexts` 引用句）。
- 展示：canvas 力导向图，**最多 30 节点 / 45 边**（超过折叠为"展开更多"）；中心节点高亮，节点大小 = 被引，颜色 = 年份。
- 交互：hover 显示标题；点击节点跳 `/p/:id`；双击展开下一跳（最多 2 跳）。
- 性能：布局在主线程外不可用（无 Worker 也可，30 节点足够快）；必须 60fps 拖拽。
- 无障碍：图必须配"列表视图"替代（同样的数据以表格呈现），否则屏幕阅读器不可用。

#### 5.11.3 被引增速（`core/metrics.ts`）

```
recent12 = 近 12 个月被引（OpenAlex counts_by_year）
trend = recent12 / max(totalCites, 1)
标签：trend > 0.4 → "正在快速上升"；0.15–0.4 → "稳定上升"；<0.15 → "经典/沉淀"
```

**必须标注**："基于 OpenAlex counts_by_year，更新于 {date}"。无数据 → 显示"—"（D-12）。

#### 5.11.4 阅读体验

- 摘要分段（按句号切，> 5 句时折叠为 3 行）。
- 选中文字 → 浮动工具条：复制 / 搜索该短语 / 解释概念（AI，P1）。
- 已读标记：进入详情 3s 后自动标记（本地），列表以浅色点提示。
- 阅读进度：详情页右侧细进度条（长页面）。

## 6. 设计系统与交互规范

### 6.1 视觉方向

**关键词**：学术严肃、信息密度高、克制、可长时间阅读。
**反例（禁止）**：紫蓝渐变 SaaS 风、玻璃拟态、大面积 emoji、圆角 20px 卡片、发光边框、滚动触发视差。

- 主色：墨黑 `#111418`（亮色正文）／暖白 `#FBFAF8`（亮色底）；深色底 `#0E1116`，面 `#161A21`。
- 强调色：琥珀 `#B8791A`（亮）/ `#E0A030`（暗）——用于"当前选中、可点击焦点、关键指标"，**不做大面积填充**。
- 语义色：成功 `#2E7D4F`、警告 `#A86A00`、危险 `#B3261E`、信息 `#2A5DB0`。
- 中性阶：9 级灰（`--n-0..--n-8`），所有边框/文字必须取自色阶，禁止随手写 hex。
- 字体：
  - 正文/UI：`ui-sans-serif, -apple-system, "Segoe UI", "Noto Sans SC", system-ui, sans-serif`
  - 论文标题：衬线 `"Noto Serif SC", "Songti SC", Georgia, serif` ——建立"这是论文"的直觉
  - 数字/指标：`ui-monospace, "SF Mono", Consolas, monospace`（表格对齐）
  - 禁止 Web Font 网络加载（免费额度 + 首屏）；只用系统字体栈。
- 圆角：4px（控件）/ 6px（卡片）/ 999px（chip）。阴影只用于浮层（抽屉、命令面板），列表项不用阴影，用 1px 分隔线。
- 栅格：桌面 12 列，内容最大宽 1440px，三栏比例 `260px | 1fr | 380px`；平板两栏；移动单栏 + 底部抽屉。
- 密度：结果卡片默认 3 行（标题 2 行 + 元数据 1 行），`compact` 模式 1 行；行高 1.5。

**渲染约定**（D-02 的落地方式，避免"手写 SPA 失控"）：

1. 每个组件导出 `render(state) => string`（返回 HTML 字符串，内部统一经 `html` 标签函数转义）。
2. 每个组件导出 `mount(root, ctx) => { update(patch), destroy() }`，`update` 只做**局部重渲染**（组件根节点 `innerHTML` 替换），不重建整个页面。
3. 组件之间不直接通信：通过 `store.dispatch(action)` + `store.subscribe(selector, cb)`。
4. 事件绑定用**事件委托**（根节点一个 listener + `data-action`），避免每次渲染后重新绑定，也避免内存泄漏。
5. 列表项必须带稳定 `data-key`（Work.id），用于 DOM 复用与滚动锚定。

### 6.4 状态管理（`public/js/store.js`）

```js
// 单一 store，四个切片
{
  query:   { raw, params, parsed },      // URL 派生，单向
  results: { items, total, page, poolSize, hasMore, loading, error, partial, sources },
  ui:      { theme, view, drawerId, paletteOpen, toast, filtersOpen, density },
  user:    { clientId, favorites: Map, collections: [], recent: [], notes: Map, quota }
}
```

规则：
- URL 是 `query` 的唯一真相：任何参数变更 → `navigate(url)` → 解析 URL → 更新 store → 订阅者重渲染。
- 异步结果必须带 `requestId`；store 丢弃 `requestId` 不是最新的响应（修复 v2 竞态 A-20）。
- 每个搜索请求配 `AbortController`，新请求发出前 abort 旧的。
- 持久化：`ui.theme`、`ui.density`、`user.*` → IndexedDB/localStorage；`results` 不持久化（可选 sessionStorage 快照用于刷新恢复，带 10 分钟有效期）。

### 6.6 无障碍（WCAG 2.1 AA 的子集，逐条可测）

- 对比度：正文 ≥ 4.5:1，大字号 ≥ 3:1（亮/暗两套都要测）。
- 所有图标按钮必须有 `aria-label`；不得用 emoji 作为唯一语义（emoji 可作装饰 `aria-hidden="true"`）。
- 焦点可见：`:focus-visible` 2px 强调色描边，**禁止** `outline: none` 无替代。
- 语义结构：`<header>/<nav>/<main>/<aside>/<footer>`，标题层级不跳级（h1→h2→h3）。
- 动态区域：结果更新用 `aria-live="polite"` + `aria-busy`；toast 用 `role="status"`。
- 抽屉/弹窗：焦点陷阱 + 打开时聚焦首元素 + 关闭时焦点归还。
- 表单：`<label for>` 或 `aria-label`；错误信息 `aria-describedby` 关联。
- 支持 200% 缩放不出现横向滚动（桌面 1280px）。
- 动效：`prefers-reduced-motion` 下禁用非必要过渡。
- 验收工具：`node scripts/a11y-audit.mjs`（静态检查 aria/label/alt/对比度 token）。

```

```

```sql
);

-- 分享快照（只读，7/30/永久）
CREATE TABLE shares (
  code TEXT PRIMARY KEY,            -- 6 位 base62
  kind TEXT NOT NULL,               -- results | evidence | report
  payload TEXT NOT NULL,            -- JSON（≤ 60KB，精简字段，无 client_id）
  title TEXT,
  owner_token TEXT NOT NULL,        -- 撤回凭证（哈希后存）
  created_at INTEGER NOT NULL,
  expires_at INTEGER
);

-- 加密云备份（服务端只见密文）
CREATE TABLE backup (
  client_id TEXT PRIMARY KEY,
  blob TEXT NOT NULL,               -- base64 密文（AES-GCM，密钥不出浏览器）
  version INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- 用户反馈（1 行/次，不存 IP）
CREATE TABLE feedback (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT, message TEXT NOT NULL, page TEXT, contact TEXT,
  ts INTEGER NOT NULL
);

-- KV 写预算监控（每次写 KV 记 1 行，用于证明未超 1000/天）
CREATE TABLE kv_write_log (
  day TEXT NOT NULL, bucket TEXT NOT NULL, n INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (day, bucket)
);

-- 客户端错误聚合（脱敏，10s 批量 1 行）
CREATE TABLE client_error (
  day TEXT NOT NULL, fingerprint TEXT NOT NULL, n INTEGER NOT NULL DEFAULT 0,
  sample TEXT, PRIMARY KEY (day, fingerprint)
);
```

**禁止**：把用户收藏/笔记写入 D1（隐私 + 写预算）；D1 不存任何可识别个人的信息。

**KV 命名空间（`CACHE`）**

| key 模式 | 值 | TTL | 写入方 |
|----------|-----|-----|--------|
| `pool:<queryHash>` | 结果池（≤ 200 条精简 Work） | 600s | Warmer 仅热词 Top 20；在线请求**不写** |
| `tr:<lang>:<sha1(text)>` | 翻译结果 | 86400s | 在线请求（每文本只写一次，先查后写） |
| `ai:<kind>:<sha1(promptId+input)>` | AI 结果 | 86400s | 在线请求 |
| `stats:hot` | 热词 Top 12 + 更新时间 | 3600s | Warmer |
| `cfg:sources` | 源开关/维护公告 | 300s | 手动 |

**写预算核算**：在线路径 KV 写 ≈ 翻译/AI 的"首次"写入（去重后日均 < 150）+ Warmer 20 次/小时 × 24 = 480。合计 < 650/天 < 1000 上限。**M1 结束后必须实测并按实测值调整**（`scripts/kv-budget.md` 记录）。

### 7.5 API 契约

统一响应信封（新端点）：

```jsonc
// 成功
{ "ok": true, "data": { ... }, "meta": { "requestId": "a1b2", "ms": 812, "cache": "l1" } }
// 失败
{ "ok": false, "error": { "code": "UPSTREAM_TIMEOUT", "message": "Crossref 响应超时", "retryable": true }, "meta": { "requestId": "a1b2" } }
```

错误码枚举（`lib/errors.ts`，前端按下表文案）：

| code | HTTP | 前端文案 |
|------|------|----------|
| `BAD_QUERY` | 400 | 检索式不完整，请补充关键词 |
| `BAD_PARAM` | 400 | 参数不合法（字段名） |
| `ALL_SOURCES_FAILED` | 503 | 数据源暂时都不可用 |
| `UPSTREAM_TIMEOUT` | 504 | 某个数据源响应慢，已使用其余结果 |
| `NOT_FOUND` | 404 | 没有找到这篇文献 |
| `RATE_LIMITED` | 429 | 请求过于频繁，请 1 分钟后重试 |
| `AI_QUOTA_EXCEEDED` | 429 | 今日 AI 额度已用完 |
| `AI_UNAVAILABLE` | 503 | AI 暂不可用，文献结果不受影响 |
| `INTERNAL` | 500 | 服务异常（已记录 requestId） |

**`GET /api/search`**

| 参数 | 类型 | 默认 | 校验 |
|------|------|------|------|
| `q` | string | — | 1..200 字符；`q` 与 `doi` 至少一个 |
| `doi` | string | — | DOI 正则 |
| `src` | csv | 核心 6 源 | 子集校验，未知源忽略并告警 |
| `from`/`to` | int | — | 1800..2100，`from ≤ to` |
| `type` | enum | all | all/journal/conference/preprint |
| `lang` | enum | all | all/zh/en（zh 时强制含 openalex） |
| `field` | csv | — | cs/physics/math/bio/med/econ |
| `sort` | enum | smart | smart/relevance/newest/cited |
| `page` | int | 1 | 1..10 |
| `limit` | int | 20 | 20/50 |

响应 `data`：

```jsonc
{
  "items": [ Work... ],          // 带 score.parts、reasons、sources
  "total": 23481,                // 池内已知总数（可能为估计，含 estimated 标志）
  "poolSize": 200, "page": 1, "limit": 20,
  "hasMore": true, "exhausted": false, "partial": false,
  "sources": [{ "id": "openalex", "name": "OpenAlex", "status": "ok", "ms": 640, "count": 42 },
              { "id": "crossref", "name": "Crossref", "status": "timeout", "ms": 4500, "count": 0 }],
  "parsed": { "intent": "topic", "terms": ["大语言模型"], "lang": "zh" }
}
```

**`GET /api/work`**（`id` 必填）：返回 `Work + references[] + citedBy[] + similar[] + metricsFetchedAt`。
**`GET /api/author`**（`id` 或 `name`）：`name` 时返回 `candidates[]`（≤ 5），必须由用户点选。
**`GET /api/trending`**（`field` 可选，`refresh=1` 仅内部 token 可用）：返回 `{ crawledAt, via, items[], nextCursor }`。
**`POST /api/ai/*`**：body 限 32KB；`papers` ≤ 12 条，每条摘要 ≤ 800 字。

### 7.6 缓存协议（分层）

| 层 | 载体 | key | TTL | 命中率预期 |
|----|------|-----|-----|-----------|
| L0 | 内存（isolate 级 Map，≤ 50 项） | queryHash | 60s | 同实例短时重复 |
| L1 | Cache API（`caches.default`） | `https://cache.internal/search/<queryHash>` | 600s | 同机房重复（~40%） |
| L2 | KV | `pool:<queryHash>` | 600s | 跨机房热点（仅 Warmer 写入） |
| 静态 | 浏览器 SW | 版本化 | 1 年（带 hash）/ 0（HTML） | — |

要点：
- `queryHash = sha1(canonical(params))`，`canonical` 必须：源排序、去默认值、trim、小写关键词。**禁止**直接 `JSON.stringify(params)`（v2 的 A-08）。
- 响应头必须带 `X-Cache: hit|miss|stale` 与 `X-Request-Id`，便于验收。
- 禁止缓存 4xx/5xx 与空结果（空结果缓存 60s 防抖即可，标记 `empty:yes`）。

### 7.7 韧性与降级

| 场景 | 行为 |
|------|------|
| 单源超时（> 4.5s） | abort 该源，标记 `timeout`，其余照常返回，`partial=true` |
| 单源 429 | 不重试（避免放大），标记 `rate_limited`，本次跳过 |
| 单源 5xx | 重试 1 次（400ms 退避），仍失败标记 `error` |
| 全部源失败 | 若有 L1/L2 旧结果 → 返回旧结果 + `stale=true`；否则 503 |
| 源健康 | **不做跨请求熔断**（KV 写不起）。改为：请求内失败即降级；跨请求健康度由 Warmer 每日聚合到 D1，`/api/status` 展示"近 24h 成功率"，前端在源被选时提示"该源近 24h 成功率 62%" |
| Workers AI 失败 | 返回 `AI_UNAVAILABLE`，前端降级为证据列表 |
| D1 失败 | 统计/配额相关功能降级（放行，不做硬阻断），日志告警 |
| 上游返回 HTML 而非 JSON | 检测 `content-type` 不匹配 → 视为源故障，记录 `parse_error` |

**并发**：`MAX_CONCURRENCY = 6`，用简单的信号量实现（`lib/infra/semaphore.ts`），避免 9 源同时打满。

### 7.8 可观测性

- 结构化日志：`console.log(JSON.stringify({ lvl, rid, route, ms, status, cache, srcs }))`；Workers 日志保留由 Cloudflare 提供（免费额度内，`observability.enabled: true` 已开）。
- `GET /api/status`（公开）：各源 24h 成功率、最近错误（脱敏）、今日配额剩余、缓存命中率（近似）、版本号。**这是验收的重要抓手**。
- Analytics Engine（可选，M6 若额度允许）：`search` 事件（1 数据点/请求）；不写则用 D1 `search_log`。
- 客户端错误：`POST /api/log` 写 D1（每日 ≤ 500 行，超出丢弃）。
- 告警：无付费告警服务 → 用 `/api/status` 的 `degraded` 标志 + 首页顶部条（当成功率 < 70% 时显示"部分数据源异常"）。

### 7.9 安全与合规

| 项 | 要求 |
|----|------|
| CORS | `Access-Control-Allow-Origin` 仅 `https://paperscout.pages.dev` + `http://localhost:8788`；不返回 `*` |
| 输入校验 | 全部参数白名单 + 长度上限；body ≤ 32KB；JSON 解析 try/catch |
| XSS | 前端模板函数默认转义；`innerHTML` 只允许来自 `html` 模板的输出；上游 HTML 一律先 strip |
| SSRF | 上游 URL 全部来自常量白名单，禁止用户 URL 直传（`/api/work?url=` 不接受任意 URL） |
| 限流 | 内存令牌桶：`search` 30 次/分/IP，`ai/*` 5 次/分/IP，`translate` 10 次/分/IP；超出 429 |
| 滥用防护 | `/api/diag` 删除（由 `/api/status` 替代，只返回聚合值，不代理任意上游）；`refresh=1` 需 header token（`X-Warmer: <secret>`，secret 存 Pages 环境变量） |
| 隐私 | 不设 cookie 追踪；client_id 仅在 localStorage；不记录 IP（限流用内存哈希，不落库）；`/about` 提供"清除我的全部数据"按钮（清 IndexedDB + localStorage） |
| 版权 | 只展示元数据与摘要片段（≤ 800 字）；不托管 PDF；"原文"跳转权利方；页面常驻免责声明 |
| 学术诚信 | AI 输出不作为创作来源，界面标注"AI 生成，需核实"；导出内容保留来源链接 |
| 合规声明 | `/about` 含：数据来源与许可（OpenAlex CC0、Crossref 元数据开放、arXiv 使用条款）、中文覆盖局限、AI 局限、联系方式 |
| 分享快照 | `/s/:code` 只读、`noindex`；payload 不含 `client_id`/笔记（除非显式勾选）；撤回凭 ownerToken；7/30 天自动过期（`expires_at`） |
| 加密备份 | 服务端只存 base64 密文（AES-GCM），密钥由浏览器 PBKDF2 派生且**永不上传**；blob 上限 256KB；`GET` 需要 `X-Client-Id` 匹配 |
| 可选源 key | `X-Source-Key` 仅用于当次上游请求；禁止写 KV/D1/日志；日志中统一替换为 `***` |
| 内容注入 | 上游摘要先 `stripTags` + 实体解码，再进模板转义；禁止把上游 HTML 直接插入 DOM |

## 10. 验收总则

详细可勾选清单见 **`docs/ACCEPTANCE.md`**。此处只定规则。

1. **分五类**：自动门禁（A）、功能（F）、交互（S）、质量（Q）、成本与性能（P）。
2. **判定优先级**：S（交互）> F（功能）> Q（质量）> P（成本）。即"界面再好看，点击没反应"一律判不通过。
3. **必选项**（标记 `[必]`）任一不通过 → 里程碑不通过。可选项（`[可]`）记录问题但不阻塞。
4. 每个迭代（里程碑）结束时 owner 只看该里程碑相关条目，避免一次验收 200 项。
5. 缺陷分级：
   - **P0**（阻断）：崩溃、白屏、数据错乱、承诺功能不存在 → 立即修，修完重跑该里程碑必选项。
   - **P1**（严重）：体验断裂（无反馈、焦点丢失、移动端不可用）、明显错误文案 → 本轮修。
   - **P2**（一般）：视觉细节、极少数场景 → 记入 backlog，可上线。
6. 返工闭环：agent 修复后必须提供"复现步骤 + 修复前后对比"，owner 只重跑失败项 + 相邻 3 项（防回归）。
7. **反向验收**（每个里程碑都做）：随机挑 3 个"没被要求改"的既有功能，确认没被改坏。

### 附录 B：查询 DSL

|------|------|------|

| `author:` | 作者 | `author:bengio` |
| `year:` | 年份或区间 | `year:2020-2024` |
| `venue:` | 期刊/会议 | `venue:neurips` |
| `type:` | 类型 | `type:preprint` |
| `doi:` | DOI 直查 | `doi:10.1038/s41586-023-06221-2` |
| 裸 DOI | 自动识别 | `10.1145/3292500` |

### 附录 C：AI Prompt 版本管理

- `prompts.ts` 导出 `PROMPT_VERSION = 'v1'`，任何提示词改动必须 +1。
- 缓存 key 必须含 `PROMPT_VERSION`（避免旧答案污染新逻辑）。
- 每次改动在 `docs/CHANGELOG.md` 记录：改了什么、为什么、预期差异。
